# Expose the OPDS Catalog on the LAN

KOReader on the Kindle reads CBZ and PDF natively but cannot reach Google Drive; its
remote sources are OPDS catalogs. Kindrop therefore mirrors the Source Folder into
Library Files and serves them as an OPDS Catalog from a dedicated `catalog` compose
service on port 8788, the only port published beyond localhost.

This amends ADR 0001: the web UI and API stay on `127.0.0.1:8787`, while the catalog
service is reachable from the LAN. To keep the exposure narrow, the catalog service
requires HTTP Basic Auth on every route except the unauthenticated `/health` endpoint
used by the compose healthcheck (it leaks only liveness, no catalog contents), with
credentials generated by Kindrop and shown in Settings; the service never calls Google
APIs, never touches OAuth tokens, and its only database writes are the download-tracking
fields of Library Files. Anything wider (WAN exposure, HTTPS, multiple users) needs a
new ADR.

## Credentials storage deviation

The original spec described Catalog credentials as "generated at bootstrap and stored
with SecretStore" (the same envelope-encrypted store used for Google OAuth tokens). The
implementation instead generates `catalog_password` on first enable (a random
`token_urlsafe(12)`) and stores it in plaintext in `app_settings`, alongside
`catalog_username`. This is an accepted deviation, not an oversight: the password must
be displayed back to the user in Settings so they can enter it into KOReader, so
encrypting it at rest would only protect it while unread; it is a low-value credential
(read-only access to comic files on a single trusted LAN, not to Google or the Kindle
Destination); and the database is already local to a single-user machine with no
external network exposure of its own. SecretStore stays reserved for the Google OAuth
tokens it was built to protect.
